# نظام الأميرة لإدارة المخزون والفواتير
## شركة الأميرة للتوريدات العامة والتجارة (Al Amira Inventory & Invoicing System)

نظام سحابي متكامل ومخصص لإدارة المخزون وفواتير المبيعات والتوريدات للشركات التجارية، صُمم خصيصاً ليلبي متطلبات الشركات والتجارة في جمهورية مصر العربية بواجهة عربية راقية (RTL)، مع دقة متناهية في الحسابات المالية، ونظام خصومات ثنائي (على مستوى البند وعلى مستوى الفاتورة)، وطباعة احترافية، وتصدير إكسل حقيقي بـ 13 ورقة عمل، ونسخ احتياطي كامل واستعادة آمنة.

---

## 1. الخصائص والميزات الأساسية

1. **حماية قائمة المستخدمين المصرح لهم (Authorized Users Protection)**:
   - جدول `authorized_users` محمي بصلاحية قراءة فقط لعملاء المتصفح الموثقين (`SELECT` فقط).
   - تم إلغاء كافة صلاحيات `INSERT` و `UPDATE` و `DELETE` على الجدول من عملاء الويب لمنع التلاعب بالقائمة البيضاء عبر REST API. التهيئة تتم حصراً عبر إجراءات الخادم الإدارية.
2. **قاعدة بيانات سحابية متقدمة (Supabase / PostgreSQL)**:
   - تطبيق مبدأ الأمان عبر **Row Level Security (RLS)** لجميع الجداول.
   - **فرض الرصيد الافتتاحي الصفري:** محفز `trg_enforce_zero_initial_stock` يرفض إنشاء أي منتج برصيد غير صفري لضمان إثبات كل رصيد بحركة مخزنية موثقة.
   - **صلاحيات صارمة على مستوى الأعمدة (Column-Level Permissions):** تم إلغاء صلاحية `UPDATE` على عمود `current_stock` للمستخدمين، ولا يمكن تعديله إلا عبر الدوال المخزونة الذرية المعتمدة (`SECURITY DEFINER`).
   - إجراءات ومعاملات ذرية مخزونة (Atomic RPC Transactions) تمنع الرصيد السالب أو تضارب العمليات المتزامنة بواسطة قفل السجلات (`FOR UPDATE`).
   - سجل حركات مخزون معصوم من التعديل أو الحذف (Immutable Audit Trail).
3. **أمان النسخ الاحتياطية**:
   - تصدير النسخ الاحتياطية يعمل بكفاءة عبر `export_full_backup()` بهيكلية JSON معيارية.
   - تم تعطيل الاستعادة المباشرة عبر المتصفح `restore_full_backup()` لمنع مخاطر تعطيل المحفزات والتنازع على أقفال الجداول، مع قصر الاستعادة على مسؤولي النظام عبر أدوات إدارة قاعدة البيانات الرسمية.
4. **تثبيت إنتاجي نظيف 100%**:
   - لا توجد أي بيانات وهمية أو تجريبية (أرقام سجل تجاري أو بطاقات ضريبية أو هواتف أو موردين أو عملاء أو منتجات افتراضية). يبدأ النظام نظيفاً وجاهزاً للتشغيل الحقيقي.
3. **محرك تشغيل هجين (Dual-Engine)**:
   - ربط سحابي مباشر مع **Supabase**.
   - محرك محلي مدمج فائق الدقة (High-Fidelity Engine) لتشغيل النظام فورياً والتجربة والاختبار بدون الحاجة لإعداد مسبق.
4. **نظام فواتير المبيعات والخصومات المزدوجة**:
   - خصم على مستوى البند (نسبة مئوية % أو مبلغ ثابت ج.م).
   - خصم عام على الفاتورة (على المجموع الفرعي).
   - مصاريف إضافية (شحن، تركيب، دمغات).
   - تفقيط وحسابات دقيقة مطابقة تماماً للمتطلبات المحاسبية.
5. **أذون الإضافة والصرف المخزني**:
   - أذون إضافة (توريد بضاعة) تزيد الرصيد لحظياً وتوثق بيانات المورد وفاتورته.
   - أذون صرف تمنع الصرف في حال عدم كفاية الرصيد وتحمي من الرصيد السالب.
6. **تسويات الجرد المخزني**:
   - حصر الفوارق بين الرصيد الدفتري والفعلي وتحديث الرصيد وتوثيق أسباب التسوية (مقتصرة على مدير النظام).
7. **طباعة مستندات احترافية (A4 Print)**:
   - فواتير مبيعات ضريبية، أذون إضافة، وأذون صرف منسقة للطباعة أو الحفظ كملف PDF مع إخفاء أدوات التحكم تلقائياً.
8. **نظام تصدير Excel حقيقي (13 ورقة عمل)**:
   - تصدير ملف `.xlsx` حقيقي يحتوي على 13 Sheet ببيانات حقيقية وخلايا رقمية تقبل العمليات الحسابية.
9. **النسخ الاحتياطي الكامل والاستعادة الآمنة**:
   - تصدير كامل البيانات بهيكلية JSON مع إصدار مخطط محدد `1.0.0` ومؤقت زمني.
   - تنبيه آلي في حال مرور أكثر من 24 ساعة على آخر نسخة احتياطية.
   - استعادة آمنة مشروطة بكتابة كلمة تأكيد "استعادة" ومعاينة عدد السجلات لمنع الأخطاء غير المقصودة.

## 3. طريقة تثبيت وإعداد قاعدة البيانات (Supabase)

1. أنشئ حساباً أو مشروعاً جديداً على [Supabase](https://supabase.com).
2. افتح قائمة **SQL Editor** داخل لوحة تحكم المشروع.
3. افتح الملف [`supabase/combined_setup.sql`](file:///d:/Projects/System_Excel/supabase/combined_setup.sql) وانسخ محتواه بالكامل.
4. الصق المحتوى في **SQL Editor** واضغط على زر **RUN**.
5. سيتم بناء الجداول، الفهارس، الإجراءات الذرية، سياسات RLS، والبيانات الأولية بنجاح.

### تجهيز الحسابين المصرح بهما (نموذج المستخدمين المتساويين في الصلاحيات - Two Equal Users)

وفقاً لمتطلبات العمل المعتمدة، فإن هذا النظام داخلي وخاص بشركة الأميرة، ولا يحتوي على تدرج هرمي (مدير مقابل موظف)، بل يعتمد على حسابين مصرح لهما بكامل الصلاحيات التشغيلية والرقابية معاً. العملاء والموردون هم سجلات أعمال فقط ولا يمتلكون أي حسابات دخول.

**خطوات التهيئة اليدوية الآمنة:**
1. من خلال لوحة تحكم Supabase، انتقل إلى **Authentication > Providers > Email**:
   - قم بإلغاء تفعيل خيار التسجيل العام (**Disable "Enable Signups"**) لمنع أي تسجيل عام.
2. انتقل إلى **Authentication > Users** واضغط **Add user > Create user** لإنشاء الحسابين:
   - **الحساب الأول**: `user1@alamira.com` (مع كلمة مرور قوية).
   - **الحساب الثاني**: `user2@alamira.com` (مع كلمة مرور قوية).
3. انسخ المعرف الفريد (`User UID`) الخاص بكل مستخدم بعد إنشائه.
4. افتح **SQL Editor** في Supabase وقم بتسجيل الحسابين في القائمة البيضاء المعتمدة (`authorized_users`):
```sql
-- إضافة المستخدم الأول
SELECT public.provision_authorized_user(
    '00000000-0000-0000-0000-000000000001', -- استبدل بـ UID الفعلي للمستخدم الأول
    'أحمد محمود',
    'user1@alamira.com'
);

-- إضافة المستخدم الثاني
SELECT public.provision_authorized_user(
    '00000000-0000-0000-0000-000000000002', -- استبدل بـ UID الفعلي للمستخدم الثاني
    'محمد علي',
    'user2@alamira.com'
);
```

## 4. إعداد الاتصال وتشغيل التطبيق

### الربط مع السحابة (Supabase):
1. افتح ملف [`index.html`](file:///d:/Projects/System_Excel/index.html) في أي متصفح حديث.
2. انقر على زر **إعدادات الربط السحابي** (أسفل شاشة الدخول).
3. أدخل:
   - **Project URL**: رابط مشروعك على Supabase (مثال: `https://xyz.supabase.co`).
   - **Anon Public Key**: المفتاح العام للمشروع (`anon public key`).
4. اضغط على **حفظ الإعدادات والاتصال**.
5. سجل الدخول بأحد الحسابين المصرح بهما (`user1@alamira.com` أو `user2@alamira.com`).
6. سيتحقق النظام سحابياً عبر Supabase Auth وسيتأكد من وجود الـ UID في جدول `authorized_users` قبل السماح بالدخول وعرض البيانات.

## 5. نشر التطبيق على الإنترنت (Hosting)

التطبيق مصمم كصفحة ويب أحادية وثابتة جاهزة للنشر على أي منصة استضافة سحابية عالمية:

### النشر عبر Cloudflare Pages:
1. ارفع ملفات المشروع أو ملف `index.html` إلى مستودع GitHub.
2. ادخل إلى لوحة تحكم [Cloudflare Dashboard](https://dash.cloudflare.com) ثم اختر **Workers & Pages**.
3. اختر **Create application > Pages > Connect to Git**.
4. اختر المستودع، وفي خانة Build Settings اتركها فارغة (Build Command: فارغ، Build output directory: `.`).
5. اضغط **Save and Deploy**. سيكون موقعك متاحاً ويعمل على مدار الساعة مجاناً.

### النشر عبر Netlify:
1. ادخل إلى [Netlify](https://www.netlify.com).
2. اسحب مجلد المشروع وأفلته في نافذة **Sites > Drop to upload**.
3. سيعمل الموقع فوراً برابط عالمي مع شهادة SSL مجانية.

## 6. التحقق واختبار السيناريو الإلزامي

تم اختبار النظام بنجاح وفق السيناريو المالي والمخزني المحدد:

```bash
node test_scenario.js
node verify_all_requirements.js
```

### ملخص نتائج اختبار السيناريو:
- **إنشاء الصنف P001**: سعر الشراء 80 ج.م، سعر البيع 100 ج.م، الرصيد الأولي 0.
- **اعتماد إذن إضافة 100 وحدة**: تم تحديث المخزون بدقة إلى **100 وحدة**.
- **إنشاء فاتورة لـ 10 وحدات بخصم بند 10% وخصم فاتورة 5%**:
  - الإجمالي الأولي (Gross): `10 × 100 = 1000 ج.م`.
  - خصم البند (10%): `100 ج.م`.
  - المجموع الفرعي (Subtotal): `900 ج.م`.
  - خصم الفاتورة (5% على 900 ج.م): `45 ج.م`.
  - الصافي النهائي المستحق: **855 ج.م** (مطابقة تامة 100%).
- **اعتماد الفاتورة**: خصم الرصيد تلقائياً إلى **90 وحدة**.
- **إعادة فتح الفاتورة وطباعتها**: المخزون ثابت عند **90 وحدة**.
- **محاولة بيع 100 وحدة والمخزون 90**: تم رفض المعاملة ومنع الرصيد السالب بنجاح.
